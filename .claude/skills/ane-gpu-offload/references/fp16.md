# fp16 weight programs

The baseline. The ANE multiplies in fp16, so an fp16 weight const is the
native, uncompressed form. Confirmed in hardware: `ANEQuantizedWeightProbeTests`
fp16 arm, max-abs 0.031 against an fp32 reference whose max is 98.

## When to use it

Only when the source weight is already bf16/fp16 and memory is not a concern.
For a quantized model, do not dequantize to fp16 to feed the ANE; use the int8
sub-skill so the ANE reads the compressed bytes. fp16 doubles the weight bytes
the ANE streams, and the ANE is bandwidth-bound.

## The MIL text (byte-exact, from `buildConvMILText`)

A `[out, in]` projection is a 1x1 conv over `[1, in, 1, S]`, which computes
`x @ w.T` per sequence position.

```text
program(1.3)
[buildInfo = dict<string, string>({{"coremlc-component-MIL", "3510.2.1"}, {"coremlc-version", "3505.4.1"}, {"coremltools-component-milinternal", ""}, {"coremltools-version", "9.0"}, {"mlxfast-program-tag", "<unique-tag>"}})]
{
  func main<ios18>(tensor<fp16, [1, IN, 1, S]> x) {
    tensor<fp16, [OUT, IN, 1, 1]> w = const()[name=string("w"), val=tensor<fp16, [OUT, IN, 1, 1]>(BLOBFILE(path=string("@model_path/weights/weight_data.bin"), offset=uint64(64)))];
    string pt = const()[name=string("pt"), val=string("valid")];
    tensor<int32, [2]> st = const()[name=string("st"), val=tensor<int32, [2]>([1,1])];
    tensor<int32, [4]> pd = const()[name=string("pd"), val=tensor<int32, [4]>([0,0,0,0])];
    tensor<int32, [2]> dl = const()[name=string("dl"), val=tensor<int32, [2]>([1,1])];
    int32 gr = const()[name=string("gr"), val=int32(1)];
    tensor<fp16, [1, OUT, 1, S]> y = conv(dilations=dl, groups=gr, pad=pd, pad_type=pt, strides=st, weight=w, x=x)[name=string("conv")];
  } -> (y);
}
```

Rules that are load-bearing:

- `mlxfast-program-tag` must be unique per weight. The descriptor's identity
  hash covers the network text only, not the blob, so two programs with the
  same text share one staging directory and one compiled program and the
  second silently computes with the first's weights (the 2026-09-02 hybrid
  collapse). Use a sha256 of the blob.
- Scalars use the bare type, `int32 gr`, not `tensor<int32, []>`. The ANE
  compiler rejects the tensor form for a scalar with `InvalidMILProgram`.
- The trailing sequence axis is padded to 32 internally on BOTH input and
  output; write and read only the real `S` elements at the padded stride.

## The weight blob (`buildConvWeightBlob`)

The `BLOBFILE(offset=64)` reads oMLX's `make_blob` chunk descriptor, not a raw
payload. Layout, matched byte for byte:

- bytes `[0]=0x01`, `[4]=0x02`: blob-level header.
- at offset 64, the chunk header: `[0..3] = EF BE AD DE` (magic), `[4] = 1`
  (type; fp16 and int8 use 1), `[8..11]` = payload byte count (little-endian
  u32), `[16..19] = 128` (absolute payload offset).
- at offset 128: the fp16 weight bytes, row-major `[OUT, IN]`.

A 64-zero-byte header mmaps without error but the compiler rejects the program
with `InvalidMILProgram`; the magic and offset fields are load-bearing.

## Compile and load

`ANEInMemoryModel(milText:weightBlob:)` stages `model.mil` and
`weights/weight_data.bin` under `NSTemporaryDirectory()/<hexStringIdentifier>`
then `compileWithQoS` and `loadWithQoS` (qos 0x15). `optionsPlist` must be a
real serialized plist, even an empty dictionary; zero bytes fails with
`InvalidCompilationParam`. Staging files are removed after load; a resident
64-program process otherwise leaves about 100 MB per program on disk.
